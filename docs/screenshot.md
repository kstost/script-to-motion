# 스크린샷으로 훑어보기 — `burnmp4.py --screenshot` 사용 안내

영상의 한 구간을 **콘택트 시트**로 만드는 방법입니다. 정해진 간격의 프레임을 480p로 찍어 이미지 한 장에 격자로 모읍니다.
영상을 틀지 않고 한 구간의 흐름을 한눈에 볼 수 있고, 칸마다 그 순간의 위치가 적혀 있어 어디를 고칠지 정확히 짚을 수 있습니다.

## 1. 한눈에

```
┌ 내영상 · 0:08.00–0:09.92 · 5프레임마다 (0.0833초) · 시트 1/4 ──────────────────────┐
│ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐                                        │
│ │  칸 1  │ │  칸 2  │ │  칸 3  │ │  칸 4  │    시간 순서: 왼쪽 → 오른쪽, 위 → 아래  │
│ └────────┘ └────────┘ └────────┘ └────────┘                                        │
│ 480 0:08.00 [op02]  485 0:08.08 [op02] …     칸 아래: 프레임 번호 · 시각 · cue      │
│ ┌────────┐ …                                                                       │
└────────────────────────────────────────────────────────────────────────────────────┘
```

| 이럴 때 | 이렇게 |
|---|---|
| 장면 전환이 어색하다, 한 순간 깜빡인다, 글자가 한 프레임 튄다 | 그 1–3초를 1–6프레임마다 |
| 한 장면이 어떻게 등장하고 머물고 빠지는지 보고 싶다 | 그 장면을 15–30프레임마다 |
| 한 장(章)이 어떻게 짜여 있는지 보고 싶다 | 그 장을 60–120프레임마다 |
| 영상 전체를 훑어보고 싶다 | 전체를 300프레임(5초)마다 |
| 에이전트에게 화면을 보여 주며 이야기하고 싶다 | 그 구간의 시트를 만들어 파일을 알려 주기 |

## 2. 준비

- `burnmp4.py` 파일 하나면 됩니다. 스킬로 만든 영상 폴더마다 한 부씩 들어 있고, 다른 곳에 두고 써도 됩니다.
- **Python 3**이 있으면 됩니다. 처음 실행할 때 `~/.cache/burnmp4-venv`에 가상환경을 만들고 Playwright와 Chromium을 그 안에 받습니다
  (몇 분 걸림, 한 번만). 시스템 파이썬과 영상 폴더에는 아무것도 설치하지 않습니다.
- MP4와 달리 **ffmpeg는 필요 없습니다**(압축하지 않음).
- 영상 폴더에 `js/cues.js`(대사 시간표)가 있어야 합니다. 스킬로 만든 영상이면 이미 있습니다.

## 3. 처음 써 보기

1. 터미널에서 영상 폴더로 갑니다.
   ```bash
   cd ~/videos/내영상
   ```
2. 앞 10초를 0.5초마다 찍어 봅니다.
   ```bash
   python3 burnmp4.py --screenshot --to 10
   ```
   화면에는 이렇게 나옵니다.
   ```
   [10:12:01] 프로젝트: /Users/나/videos/내영상
   [10:12:01] 스크린샷: 0:00.00–0:10.00 · 30프레임마다(0.5초) · 20칸 · 칸 854×480 · 4×6칸씩 시트 1장 · 동시 2 · 자막 있음
   [10:12:02] 시트 1/1: 브라우저 — GPU · Metal · Apple M3 Pro · chrome · 영상 불러오는 중 (0:00.00–0:09.50, 20칸)
   진행 45.0% · 남은 약 0:12 · 9/20 프레임 · 경과 0:20 · 초당 0.95장
   [10:12:40] 시트 1/1: 완료
   [10:12:40] 완성: /Users/나/videos/내영상/screenshots — 0m00.00s-0m10.00s_g30_01.jpg (1장, 20칸) · 걸린 시간 0.6분
   ```
3. `screenshots/` 폴더의 이미지를 엽니다. 맥이면 `open screenshots`로 Finder에서 열 수 있습니다.

영상 폴더 밖에서 실행할 때는 폴더(또는 그 `index.html`)를 맨 앞에 적습니다.
```bash
python3 ~/tools/burnmp4.py ~/videos/내영상 --screenshot --to 10
```

## 4. 재생하다가 `A` 키로 만들기

브라우저로 영상을 보다가 확인하고 싶은 순간에 **`A`**를 누르면, 그 순간의 **앞뒤 1초를 10프레임마다** 찍는 명령이 클립보드에 복사됩니다.
한글 입력 상태에서도 동작하고, 화면에 「스크린샷 명령 복사됨 · 0:10.66–0:12.66」이 잠깐 뜹니다.

```
--screenshot --from 10.66 --to 12.66 --gapframe 10 --fast --jobs 4
```

1. 영상을 보다가 `A`를 누릅니다(같은 순간에 `S`를 누르면 위치와 대사가 복사됩니다 — 메모에 쓰기 좋습니다).
2. 터미널에서 영상 폴더로 가서 `python3 burnmp4.py `를 치고 붙여 넣은 뒤 실행합니다.
   ```bash
   cd ~/videos/내영상
   python3 burnmp4.py --screenshot --from 10.66 --to 12.66 --gapframe 10 --fast --jobs 4
   ```
3. `screenshots/`에 그 2초짜리 시트가 생깁니다(60fps면 12칸, 한 장).

- 복사되는 명령에는 영상 폴더 이름이 없습니다. 그래서 **영상 폴더 안에서** 실행합니다.
- 영상 처음·끝 근처에서는 구간이 0초와 영상 길이를 넘지 않게 맞춰집니다(예: 0.3초에서 누르면 `--from 0.00 --to 1.30`).
- `--fast`(한 번만 찍기)와 `--jobs 4`(브라우저 4개)가 들어 있어 빨리 끝납니다. 더 꼼꼼히 보려면 붙여 넣은 뒤 `--fast`를 지우세요.

## 5. 상황별 명령

영상 폴더 안에서 실행한다고 보고 적었습니다.

```bash
# 장면 전환 한 곳을 프레임 단위로 (11–12.5초, 2프레임마다)
python3 burnmp4.py --screenshot --from 11 --to 12.5 --gapframe 2

# 모든 프레임 (1초 = 60칸 = 시트 3장)
python3 burnmp4.py --screenshot --from 30 --to 31 --gapframe 1

# 프레임 딱 하나 (12.5초의 한 장면) — 끝을 시작보다 한 프레임 뒤로
python3 burnmp4.py --screenshot --from 12.5 --to 12.52 --gapframe 1

# 한 장면의 흐름 (40–55초, 0.25초마다)
python3 burnmp4.py --screenshot --from 40 --to 55 --gapframe 15

# 한 장의 구성 (5:47–8:48, 2초마다)
python3 burnmp4.py --screenshot --from 347 --to 528 --gapframe 120

# 영상 전체 (5초마다) — 브라우저 3개로 빨리
python3 burnmp4.py --screenshot --gapframe 300 --jobs 3

# 한 장에 칸을 더 많이 (6열 × 8줄 = 48칸)
python3 burnmp4.py --screenshot --from 0 --to 60 --cols 6 --rows 8

# 자막 없이, 무손실 PNG로
python3 burnmp4.py --screenshot --from 8 --to 15 --no-captions --png

# 다른 폴더에 저장 (그 폴더는 통째로 비우지 않음)
python3 burnmp4.py --screenshot --from 8 --to 15 --out ~/Desktop/시트
```

## 6. 선택지

| 선택지 | 뜻 | 기본값 |
|---|---|---|
| `--screenshot` | MP4 대신 콘택트 시트를 만듭니다 | (꺼짐) |
| `--gapframe N` | N프레임마다 한 칸. 60fps에서 1 = 모든 프레임, 2 = 1/30초, 6 = 0.1초, 15 = 0.25초, 30 = 0.5초, 60 = 1초, 300 = 5초 | 30 |
| `--from SEC` · `--to SEC` | 구간(초). 소수도 됩니다(`12.5`) | 처음 · 끝 |
| `--cols N` · `--rows N` | 시트 한 장의 열 · 줄 수. 칸이 넘치면 다음 장으로 | 가로 영상 4 · 6, 세로 영상 8 · 3 |
| `--fps N` | 프레임 번호와 간격을 세는 기준 | 60 |
| `--out DIR` | 저장 폴더 | 영상 폴더의 `screenshots/` |
| `--png` | 무손실 PNG (파일이 큼) | JPEG 화질 90 |
| `--no-captions` | 자막 없이 | 자막 있음 |
| `--fast` | 프레임마다 한 번만 찍기 — 빠르지만 장면이 크게 바뀌는 순간 한 칸이 바로 앞 그림일 수 있음 | 두 번 찍어 같을 때까지 |
| `--jobs N` | 동시에 만들 시트 수(= 브라우저 수) | 맥 2, 그 밖 1 |
| `--no-gpu` | 그래픽 칩 없이 소프트웨어로 그리기 — 화면이 깨질 때 | GPU 사용 |
| `--no-font-check` | 글꼴 검사 끄기 | 켜짐 |
| `--footage DIR` | 영상 클립의 렌더용 프레임 폴더 | `media/render-stills` |
| `--no-venv` | 가상환경 없이 지금 파이썬으로 (Playwright가 설치되어 있어야 함) | 가상환경 |

이 모드에서 쓰지 않는 것: `--res`(늘 480p), `--codec` · `--quality` · `--encoder`(압축하지 않음), `--no-audio`(소리 없음),
`--chunk`(시트 한 장이 작업 단위).

## 7. 시트 읽는 법

- **순서:** 왼쪽에서 오른쪽, 위에서 아래로 시간이 흐릅니다. 칸 사이 간격은 `--gapframe` 프레임입니다.
- **칸:** 영상과 같은 화면을 480p로 줄여 찍은 것입니다(가로 영상 854×480, 세로 영상 480×854). 칸마다 얇은 테두리가 있습니다.
- **칸 아래 글:** `485  0:08.08  [op02]`
  - `485` — 프레임 번호. 영상 처음부터 센 번호(60fps 기준, 0부터)입니다.
  - `0:08.08` — 시각(분:초.백분의 일초). 재생 중 `S` 키가 복사하는 것과 같은 꼴입니다.
  - `[op02]` — 그 시각에 읽히고 있는(또는 마지막으로 시작한) 대사의 id. 대사가 시작되기 전이면 비어 있습니다.
- **맨 위 한 줄:** 영상 폴더 이름 · 이 장의 첫 칸–마지막 칸 시각 · 간격 · 몇 번째 장인지.
- **고칠 곳을 말할 때:** 칸 아래 글을 그대로 적으면 됩니다. 「`485 0:08.08 [op02]` 칸에서 제목이 잘려요」처럼요.

## 8. 파일과 폴더

- **이름:** `<시작>-<끝>_g<간격>_<번호>.jpg` — 예: `0m08.00s-0m15.00s_g5_01.jpg`, `…_02.jpg`. 시작·끝은 명령에 준 구간입니다.
- **실행할 때마다 `screenshots/`를 비웁니다.** 폴더에는 늘 마지막으로 만든 시트만 남습니다.
  - 비우는 때는 새 시트가 **다 만들어진 뒤**입니다. 중간에 멈추거나 실패하면 전에 있던 시트가 그대로 남습니다.
  - 남겨 둘 시트는 다음 실행 전에 다른 곳으로 옮기세요.
  - `--out`으로 다른 폴더를 주면 그 폴더는 통째로 비우지 않고, 전에 만든 시트 파일(위 이름 꼴)만 지웁니다.
- **보관:** `screenshots/`는 검토용입니다. 스킬의 검사(`check.mjs`)는 이 폴더를 보지 않습니다. git을 쓴다면 `.gitignore`에 `screenshots/`를 넣으세요.
- **글꼴:** 칸 아래 글과 머리말은 영상 폴더에 설치된 OFL 글꼴(D2Coding, Pretendard)로 씁니다.

## 9. 시간과 크기

- **칸 수** = 구간 길이(초) × fps ÷ 간격. **시트 수** = 칸 수 ÷ (열 × 줄), 올림.

  | 구간 | 간격 | 칸 | 시트(4×6) |
  |---|---|---|---|
  | 2초 (`A` 키) | 10 | 12 | 1 |
  | 7초 | 5 | 84 | 4 |
  | 15초 | 15 | 60 | 3 |
  | 3분 | 120 | 90 | 4 |
  | 41분 전체 | 300 | 약 490 | 21 |

- **걸리는 시간:** 칸 수에 비례하고, 시트마다 영상을 한 번 불러오는 시간이 더해집니다. 처음 몇 칸은 느리게 보일 수 있습니다.
  시작하고 잠시 뒤 진행 줄의 「남은 약 …」을 보세요. 빨리 끝내려면 `--fast`, `--jobs`를 씁니다.
- **시트 이미지 크기:** 가로 영상 4×6칸이면 약 3500×3250 픽셀, 세로 영상 8×3칸이면 약 4000×2800 픽셀. JPEG라 보통 몇 MB 안쪽입니다.
  이미지 뷰어에서 확대해 보세요.

## 10. 그림이 영상과 같은 이유

MP4를 만들 때와 같은 방식으로 찍습니다. 칸마다 그 시각(프레임 번호 ÷ fps)으로 영상을 옮기고, 데모와 화면이 다 그려질 때까지 기다린 뒤 찍습니다.
재생하는 게 아니라서 컴퓨터가 느려도 그림이 달라지지 않습니다. 자막도 영상과 같은 위치·크기로 들어갑니다(`--no-captions`로 뺌).
기본으로 같은 순간을 두 번 찍어 같을 때까지 확인합니다. `--fast`는 한 번만 찍어 빠르지만, 장면이 크게 바뀌는 순간의 칸이 바로 앞 그림으로
찍힐 수 있습니다. 칸이 480p라 아주 작은 글씨는 흐릴 수 있습니다 — 글자를 자세히 볼 곳은 `--res 1080p` MP4나 브라우저로 확인하세요.

## 11. 영상 클립이 들어간 영상

녹화 화면이나 생성 영상 같은 클립(`js/media-src.js`)이 있으면, 클립 화면은 미리 잘라 둔 프레임으로 찍습니다. 시트(480p)용으로 한 번 잘라 두세요.
```bash
node <스킬 폴더>/scripts/stills.mjs . --out media/render-stills --fps 60 --scale 0.4444
```
없으면 burnmp4.py가 이 명령을 알려 주고 멈춥니다. MP4(1080p)용으로 이미 잘라 두었다면 그것을 써도 됩니다(조금 더 큰 그림을 줄여 씀).

## 12. 멈추고 이어 하기

`Ctrl+C`로 멈추면 「멈췄습니다. 끝난 시트 n/N장은 남겨 두었습니다」라고 알립니다. **같은 명령**을 다시 실행하면 다 만든 시트는 건너뛰고 이어서 만듭니다.
그사이 영상 파일(index.html, css, js 등)을 고쳤으면 처음부터 다시 만듭니다. 구간이나 간격을 바꾸면 새 작업으로 봅니다.

## 13. 에이전트와 함께 리뷰하기

1. 보다가 문제인 순간에 `S`(위치·대사 복사)와 `A`(시트 명령 복사)를 누릅니다.
2. `A`의 명령으로 시트를 만듭니다.
3. 에이전트에게 `S`로 복사한 줄과 함께 "screenshots에 시트 만들었어"라고 알려 줍니다. 공유 폴더에 있으면 에이전트가 그 이미지를 직접 엽니다.
4. 이야기할 때는 칸 아래 글(`485 0:08.08 [op02]`)로 칸을 가리킵니다. 에이전트도 같은 표기로 답합니다.

## 14. 문제 해결

| 이런 말이 나오면 | 뜻과 할 일 |
|---|---|
| `필요한 것이 없습니다: 폴더가 없습니다: …` | 준 폴더가 없습니다. 경로를 확인하세요 |
| `… 에 index.html이 없습니다` | 영상 폴더가 아닙니다. `index.html`이 있는 폴더를 주세요 |
| `영상 프로젝트 폴더를 알려 주세요` | 인자 없이 실행했는데 지금 폴더에 `index.html`이 없습니다. 영상 폴더로 가서 실행하거나 폴더를 적으세요 |
| `js/cues.js 가 없습니다` | 대사 시간표가 없습니다. 스킬의 `tts.mjs`로 먼저 만듭니다 |
| `범위가 비었습니다 (영상 길이 …초)` | `--from`이 영상 길이를 넘었거나 `--to`가 `--from`보다 앞입니다 |
| `--gapframe 은 1 이상이어야 합니다` | 간격은 1 이상의 정수입니다 |
| `영상 클립 N개의 렌더용 프레임 — 먼저 …` | 11번처럼 클립 프레임을 잘라 둡니다 |
| `파일 N개를 받지 못함 — 처음부터 다시 (2/3)` | 영상 파일 일부를 브라우저가 못 받아 그 시트를 다시 만듭니다. 세 번 실패하면 멈춥니다 |
| `글꼴 경고 — 시스템 글꼴 "…"이 그린 글자` | 영상의 어떤 글자가 설치된 OFL 글꼴이 아닌 시스템 글꼴로 그려졌습니다. 에이전트에게 알려 고치세요 |
| `N분 동안 불러오기가 나아가지 않았습니다` | 영상을 불러오다 멎었습니다. 마지막 상태(어느 작품을 준비하던 중인지)와 함께 알려 주세요 |
| `WebGL2로 그릴 수 있는 Chrome을 띄우지 못했습니다` | 브라우저가 없거나 깨졌습니다. 안내대로 표시 파일을 지우고 다시 실행하면 Chromium을 새로 받습니다 |
| 칸이 비어 보이거나 깨져 보임 | `--no-gpu`로 다시 해 보세요. 그래도 같으면 그 칸의 라벨과 함께 알려 주세요 |

## 15. 자주 묻는 질문

**왜 480p인가요? 더 크게는 안 되나요?**
시트는 흐름을 보는 용도라, 칸을 작게 해 한 장에 많이 담고 빨리 만듭니다. 크게 보고 싶은 순간은 `--res 1080p`로 그 구간의 MP4를 만들어 보세요.

**한 장에 칸을 더 많이(적게) 넣을 수 있나요?**
`--cols`(열)와 `--rows`(줄)로 바꿉니다. 칸 크기는 그대로라 칸이 많을수록 이미지가 커집니다.

**프레임 하나만 찍을 수 있나요?**
`--from 12.5 --to 12.52 --gapframe 1`처럼 끝을 시작보다 한 프레임(60fps면 약 0.017초) 뒤로 주면 칸 하나짜리 시트가 됩니다.

**소리도 들어가나요?**
아니요. 이미지라서 소리는 없습니다.

**지난번 시트가 사라졌어요.**
실행할 때마다 `screenshots/`를 비웁니다(8번). 남겨 둘 시트는 다음 실행 전에 옮기거나, `--out`으로 다른 폴더에 저장하세요.

**맥에서 빨리 하려면?**
맥에서는 기본으로 그래픽 칩(Metal)을 씁니다. `--jobs 3`–`4`와 `--fast`를 함께 쓰면 가장 빠릅니다. 메모리가 부족하면 `--jobs`를 줄이세요.

**MP4 만들기와 같이 돌려도 되나요?**
됩니다. 서로 다른 작업 폴더를 씁니다. 다만 둘 다 브라우저를 띄우므로 컴퓨터가 버거우면 하나씩 하세요.
